# v9 — Meridian 2.0 — SQLite backend

## Objective

v9 is the architectural pivot from file-per-artifact Markdown to a **SQLite data layer** for all delivery work (epics, versions, sprints, user stories, decisions, board). Phase documents — scope, stack, security, architecture, principles, and the decision stub `11_decisions.md` — remain human-readable Markdown because they define project gates and agent context at init. The current repository state is preserved on branch `meridian-v1-old`; `main` carries Meridian 2.0 with schema, migration tooling, updated kit scripts, and monitor reads from `.meridian/meridian.db`. Managers keep the same workflows (`/create-us`, `/sync-board`, `/status`) but persistence moves under the hood.

## Done criteria

v9 is `complete` when: (1) schema and bootstrap create a valid `.meridian/meridian.db`; (2) migration script imports 100% of dogfood delivery artifacts with verification report; (3) `validate_meridian.py` and `generate_board.py` operate on SQLite; (4) kit create/refine/complete paths write to the database; (5) app-desktop Board and Deliverables read from SQLite; (6) `06_database.md` and `05_architecture.md` document the Markdown vs DB boundary; (7) `meridian-v1-old` branch exists with the pre-migration tree and cutover steps are documented. Manager validates on dogfood project folder end-to-end without manual `.md` edits for new US.
