# US-0112 — app-desktop monitor loads delivery data from SQLite

**As** Process Manager,
**I want** the desktop monitor to load epics, versions, sprints, and user stories from SQLite,
**so that** I see the same delivery state the kit writes without relying on globbed Markdown files.

## Intent

### Acceptance

- [ ] When `{packageRoot}/.meridian/meridian.db` exists, `loadMeridianProjectCore()` and `loadMeridianProjectSupplement()` read from DB via new `createSqliteDocsRoot()` adapter instead of `MeridianDocsRoot` file globs for delivery folders.
- [ ] Board kanban columns render US `status` from DB rows; `deriveBoardFromStories()` input comes from DB loader.
- [ ] Deliverables tab lists epics/versions/sprints from DB with same UI as today.
- [ ] Version and epic filters reuse existing monitor filter contexts (EPIC-04) — no second filter state.
- [ ] Error banner when DB missing: "Run bootstrap + migration" with kit command hints.
- [ ] `cd app-desktop && pnpm build` exits 0.

### Why

The monitor is the manager's primary visibility surface. If kit writes to SQLite but the app still globs `docs/us/*.md`, the board shows stale or empty data after cutover. This US completes the read path for Meridian 2.0 in the Vite app using the dev HTTP bridge pattern until Tauri (v7) ships.

### Where

**v9-S4**, depends on **US-0111** (DB populated by kit). Blocks **US-0114** (repo cutover with working product). Extends EPIC-04 monitor — new data source adapter only.

## Plan

### Approach

- Add `app-desktop/src/features/folder/sqlite-docs-root.ts` implementing `MeridianDocsRoot` by calling new dev endpoint `GET /api/meridian/db?packageRoot=...&entity=stories` in `vite-file-server.ts` — keeps browser bundle free of native sqlite bindings (SRP: HTTP adapter layer only).
- Extend `vite-file-server.ts` middleware to invoke `python3 .agent/scripts/meridian_db_export.py --json stories` (read-only subprocess) using same pattern as `vite-meridian-validate.ts`.
- Branch in `project-loader.ts`: if `probeSqliteDb(packageRoot)` succeeds, use sqlite root for delivery entities; phase docs still load via existing file/HTTP root.
