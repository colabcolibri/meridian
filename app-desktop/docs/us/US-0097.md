# US-0097 — Pagination and page size in planning list webviews

**As** Process Manager,
**I want** planning list views to show a configurable page size with pagination,
**so that** large `docs/` trees stay fast and scannable without rendering hundreds of rows at once.

## Intent

### Acceptance

- [x] **Open Versions**, **Open Sprints**, and **Open Epics** show a footer pager: **Show** (25 / 50 / 100), range text (`1–50 of N`), **Prev** / **Next**, and page indicator.
- [x] Default page size is **50**; first page shows items 1–50 after filters apply.
- [x] Changing version filters resets to page 1; page size and current page persist in webview state across reloads.
- [x] Board kanban is **out of scope** (separate US for per-column pagination).
- [x] `pnpm test` includes `list-pagination.test.ts`.

### Why

After splitting Deliverables into three tabs, managers with many sprints or epics see long scroll lists. Pagination keeps the webview responsive and matches the monitor pattern of bounded lists. Sort asc/desc remains a separate story.

### Where

Post v4-S5 extension polish (EPIC-05 read surface). Depends on US-0094 list views. Unblocks US-0098 (board column pagination) without mixing kanban rules into list UX.

## Plan

### Approach

- `domain/list-pagination.ts` for pure page math; shared `PAGINATION_SCRIPT` + styles in `webview-common.ts`.
