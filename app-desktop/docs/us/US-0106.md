# US-0106 — Database bootstrap and .meridian layout

**As** Process Manager,
**I want** a bootstrap step that creates the SQLite database in my product folder,
**so that** new and migrated projects have a predictable `.meridian/` layout without manual setup.

## Intent

### Acceptance

- [ ] `python3 .agent/scripts/bootstrap_meridian_db.py <package-root>` creates `.meridian/meridian.db` applying all pending migrations from `.agent/migrations/`.
- [ ] `.meridian/` added to kit gitignore baseline (`references/gitignore-baseline.md`); `meridian.db` not committed.
- [ ] Re-run is idempotent: second run reports "already up to date" and does not duplicate `schema_migrations` rows.
- [ ] Fails with exit code 1 and message if `docs/` fingerprint missing (`00_scope.md` or `us/US-*.md` absent).
- [ ] `PRAGMA journal_mode=WAL` set on connect for concurrent monitor reads during writes.

### Why

Without a standard bootstrap, every agent and script would invent its own DB path. A single `{packageRoot}/.meridian/meridian.db` aligns with `.meridian/projects.json` at kit root (EPIC-13) and keeps the `docs/` tree for phase documents only. Managers run bootstrap once at cutover or on `/init-meridian` for greenfield projects.

### Where

**v9-S1**, depends on **US-0105** schema. Blocks **US-0107** migration (needs target DB). Complements **US-0113** documentation of folder layout.

## Plan

### Approach

- Add `.agent/scripts/bootstrap_meridian_db.py` as thin CLI wrapper calling `meridian_db.bootstrap(package_root)` from US-0105 — no duplicate migration logic (DRY).
- In `meridian_db.connect()`, call `PRAGMA journal_mode=WAL` and `PRAGMA foreign_keys=ON` before any DDL/DML so monitor HTTP reads do not block kit writes during dev.
- Update `.agent/skills/init-project/references/gitignore-baseline.md` with `.meridian/meridian.db` entry; dogfood `app-desktop/.gitignore` if not already covered by parent patterns.
