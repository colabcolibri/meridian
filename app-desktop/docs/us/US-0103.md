# US-0103 — Codex IDE adapter sync

**As** Process Manager using OpenAI Codex,
**I want** the Meridian kit to sync Codex adapters the same way it does for Cursor and Claude,
**so that** workflows and agents work in Codex after Install Harness without manual copy.

## Intent

### Acceptance

- [x] **`sync_cursor_kit.sh`** adds `sync_codex()` with `--codex-only` flag; default install syncs Cursor, Claude, and Codex together.
- [x] **Skills:** `.agent/skills/*` symlinked to `.agents/skills/`; kit `doc.md` → `meridian-authoring/SKILL.md`.
- [x] **Workflows:** `.agent/workflows/*.md` exposed as `.agents/skills/workflow-<name>/SKILL.md` (prefix avoids collision with kit skills such as `create-epic`).
- [x] **Agents:** `.codex/agents/<name>.toml` generated from `.agent/agents/*.md` frontmatter with `# meridian-kit-generated` marker and orphan prune.
- [x] **`AGENTS.md`** at repo root symlinked from `.agent/rules/AGENTS.md` when safe (skip existing real files).
- [x] **`install-meridian-kit.sh`** appends `.agents/skills/`, `.codex/`, `AGENTS.md` to gitignore; supports `--codex-only`.
- [x] **Docs:** `IDE_ADAPTERS.md`, `KIT_README.md`, `ARCHITECTURE.md`, `instruction-surfaces.md`, `gitignore-baseline.md` document Codex mapping.
- [x] **`validate_meridian.py`** warns when `.agents/skills/` or `.codex/` missing after kit present.

### Why

US-0100 limited surgical sync to `.cursor/` and `.claude/`. Teams adopting Codex still had to wire skills and subagents by hand, and Codex removed custom prompts in favor of skills — Meridian workflows must appear under `.agents/skills/`. This slice extends the same non-destructive adapter policy to Codex without changing the committed `.agent/` source.

### Where

Release **v2.05** (`v2.05-S1`), second wave of **EPIC-12** (kit distribution). Depends on **US-0100** (install + surgical sync foundation). Pairs with **US-0104** (extension onboarding) in the same release but does not block it.
