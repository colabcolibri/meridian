# US-0079 — Deliverables screen redesign

**As** Process Manager,
**I want** the Deliverables screen to communicate version and epic progress visually,
**so that** I can assess delivery health across releases without reading counts and percentages in plain text.

## Intent

### Acceptance

- [x] Each version block has a visually dominant progress indicator (bar or ring) that conveys completion at a glance — "32/32 · 100%" is not hidden in small grey text.
- [x] Sprint chips inside a version use color to communicate status: complete sprints look different from active or planned ones — not all identical grey pills.
- [x] Epic rows include an inline progress bar or visual fill in addition to the "X/Y · Z%" count.
- [x] Planned versions (e.g. v4, v5) have a visually distinct treatment from active/complete versions — muted, outlined, or labeled — so the user understands they are future scope.
- [x] Version status badge ("complete", "active", "planned") is visually prominent, not a small text chip that blends with the background.

### Why

The Deliverables screen today is a hierarchy of text. Version progress is written as "32/32 US · 100% · complete" in small grey beneath the title — the same weight as a subtitle. Sprint chips are a horizontal run of identical grey pills; whether a sprint is done or active is not distinguishable without reading the label. Epic rows show a percentage on the right but have no visual fill. This story promotes all three levels to actual visual language: progress becomes a bar, sprint status becomes color, version state becomes a badge with presence.

### Where

Third story in v3 / EPIC-11 — depends on US-0077 for nav context. Deliverables is a read-only view over `docs/versions/`, `docs/epics/`, and `docs/us/` data already loaded. No new data fetching required. This story does not change how version or epic files are parsed — only how their data is rendered.
