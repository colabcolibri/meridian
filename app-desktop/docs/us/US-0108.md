# US-0108 — Migration script — import decisions and board history

**As** Process Manager,
**I want** decision log entries and board snapshots migrated to SQLite,
**so that** governance history and kanban state are queryable alongside user stories in Meridian 2.0.

## Intent

### Acceptance

- [x] `migrate_md_to_sqlite.py --decisions` (or step 2 flag) imports every `docs/decisions/YYYY-MM-DD.json` file preserving entry order and fields per `decision-schema.md`.
- [x] Stores latest `docs/kanban/board.json` as one row in `board_snapshots` with `source='import'` and full JSON payload.
- [x] Verification report: decision entry count equals sum across JSON files; board snapshot card count equals `user_stories` row count.
- [x] Dogfood run completes with zero errors after US-0107 delivery import.
- [x] Re-run upserts decisions by `(date, entry_index)` without duplicates.

### Why

Decisions are append-only JSON today; the board is derived but managers may rely on its last-known state for demos. Migrating both ensures the monitor and `/status` can eventually query one database for governance history without opening scattered files.

### Where

**v9-S2**, depends on **US-0107** (US rows must exist for board FK integrity). Blocks **US-0109** and **US-0110**.

## Plan

### Approach

- Extend `migrate_md_to_sqlite.py` with `--decisions-only` and default full migration (delivery + decisions + board) so one entrypoint covers v9-S2.
- Parse decision files using same JSON schema checks as `validate_meridian.py` decisions loop — extract shared `validate_decision_file()` into `meridian_db.py` or small `meridian_decisions.py` helper to avoid duplicating schema rules (DRY).
- Store `board.json` verbatim in `board_snapshots.payload`; also compute `card_count` column for quick verification without parsing JSON in SQL.
