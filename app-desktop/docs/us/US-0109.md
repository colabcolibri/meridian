# US-0109 — Validator reads delivery artifacts from SQLite

**As** Process Manager,
**I want** `validate_meridian.py` to validate delivery artifacts from SQLite,
**so that** CI and `/status` enforce the same rules without parsing hundreds of Markdown files.

## Intent

### Acceptance

- [ ] When `{packageRoot}/.meridian/meridian.db` exists, `validate_meridian.py` loads epics, versions, sprints, US from DB instead of globbing `docs/epics|versions|sprints|us/`.
- [ ] Reconstructs in-memory markdown stubs from DB columns and runs existing `validate_*_structure()` / `validate_us_semantics()` from `meridian_section_contracts.py` — no duplicated rule logic.
- [ ] Phase docs (`00`–`11`) still validated from `.md` on disk.
- [ ] `python3 .agent/scripts/validate_meridian.py app-desktop` exits 0 on fully migrated dogfood.
- [ ] `--md-only` flag forces legacy filesystem mode during transition.
- [ ] Clear stderr message when DB missing: suggests `bootstrap_meridian_db.py` + `migrate_md_to_sqlite.py`.

### Why

The validator is the enforcement layer for Meridian protocol. If kit skills write to SQLite but validation still globs `docs/us/`, managers get false passes or false failures. Retargeting validation to the DB makes SQLite the real source of truth and unblocks board generation and monitor reads.

### Where

**v9-S3**, depends on **US-0108** (populated DB). Blocks **US-0110** and **US-0111**. Refactors `validate_meridian.py` load layer only — rules stay in `meridian_section_contracts.py`.

## Plan

### Approach

- Add `meridian_db.load_delivery_artifacts(package_root) -> DeliveryBundle` dataclass returning paths-as-virtual-names plus reconstructed text for each entity, consumed by existing validate loops with minimal `validate_meridian.py` changes.
- Branch in `main()` after resolving `package_root`: if `resolve_db_path().exists()` and not `--md-only`, use DB loader; else fall back to current glob (transition safety).
- Board cross-check: compare `board_snapshots` latest payload ids vs `user_stories` table when DB mode active.
