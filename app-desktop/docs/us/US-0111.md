# US-0111 — Kit write path persists artifacts to database

**As** Future VSCode User (via kit agents),
**I want** create, refine, and complete workflows to write delivery artifacts to SQLite,
**so that** agents follow the same slash commands without manually editing Markdown files.

## Intent

### Acceptance

- [ ] `meridian_db.py` exposes CRUD: `create_user_story()`, `update_user_story()`, `create_epic()`, `create_version()`, `create_sprint()`, `append_decision()`.
- [ ] CLI helpers: `meridian_db_cli.py create-us`, `refine-us`, `complete-us` callable from agent Bash steps.
- [ ] `/create-us` skill updated to call CLI instead of Write on `docs/us/US-XXXX.md` when DB exists.
- [ ] Next US id allocated via `SELECT MAX` or `us_id_seq` table — format `US-XXXX` zero-padded.
- [ ] After write, auto-invokes `generate_board.py` (subprocess) when `ready` or `status` changes affect board.
- [ ] Kit `MERIDIAN.md` or `sync-board` workflow documents DB-first path.

### Why

Agents today use Write tool on `docs/us/US-XXXX.md`. Meridian 2.0 requires the same narratives but persisted relationally. Without retargeting skills, managers would have split brain: some US in DB, some on disk. This US is the protocol cutover for all write workflows.

### Where

**v9-S3**, depends on **US-0109** (validation confirms writes). Blocks **US-0112** (monitor reads what skills write). Touches `.agent/skills/create-user-story`, `refine-user-story`, `complete-user-story`, `update-decisions-log`.

## Plan

### Approach

- Centralize all DML in `meridian_db.py` — skills never open sqlite3 directly; they call `python3 .agent/scripts/meridian_db_cli.py <command>` with JSON stdin for body sections (single responsibility, testable).
- Update `create-user-story/SKILL.md` procedure step 5: "if `resolve_db_path` exists → `meridian_db_cli create-us`; else legacy Write path" during transition window.
- `refine-us` sets `ready=1` column; `complete-us` updates `status` and Record section columns; both call `validate_us_structure()` before commit.
