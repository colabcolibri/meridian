# US-0094 — Versions, Sprints, and Epics editor tabs in VS Code extension

**As** Process Manager,
**I want** separate editor tabs for versions, sprints, and epics instead of one mixed Deliverables view,
**so that** I can navigate releases, execution slices, and capabilities without redundant filters on every surface.

## Intent

### Acceptance

- [x] **Meridian: Open Versions** — lists all `docs/versions/` with progress and expandable detail; **no version filter chips**.
- [x] **Meridian: Open Sprints** — lists `docs/sprints/` scoped by **version filter** (All / None / multi-select, same pattern as Board).
- [x] **Meridian: Open Epics** — lists `docs/epics/` scoped by **version filter** only (All / None / multi-select); no redundant epic chip row.
- [x] Row click opens the matching `.md` file; webviews refresh on `docs/` changes.
- [x] **Open Deliverables** remains as alias to **Open Versions** (no breaking change).
- [x] Commands sidebar and **View → Meridian** menu list the three views.
- [x] `pnpm test` passes.

### Why

Deliverables merged versions, sprints, and epics into one accordion with a version filter that duplicated the Board. Splitting views matches how managers think: releases (versions), timeboxes (sprints), and capabilities (epics) — each with the filters that matter for that slice only.

### Where

v4-S5 after go-live. Unblocks clearer IA before v5 authoring commands. Board filters unchanged.
