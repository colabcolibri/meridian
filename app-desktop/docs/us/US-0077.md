# US-0077 — Header and navigation redesign

**As** Process Manager,
**I want** the app header and tab navigation to communicate where I am and what project is open,
**so that** I can orient myself at a glance without reading page text or guessing which tab is active.

## Intent

### Acceptance

- [x] Header area shows the Meridian logo/wordmark and the name or path of the currently opened `docs/` folder.
- [x] Active tab is distinguished by an underline or highlight treatment — not a filled blue button — so it reads as a selected state rather than a call-to-action.
- [x] Page subtitle (e.g. "Status of each user story") is integrated into the header row or directly below it with enough visual weight to be readable on first view.
- [x] Navigation style is consistent across all six tabs with no tab looking like a primary action button.

### Why

Today the header has no project identity — the app opens to a flat row of grey text tabs with a solid blue button marking the active one. The blue button style conflicts with every other CTA in the UI and makes the selected tab look like "click me" rather than "you are here." The page subtitle below is too small and faint to orient the user. This story strips the nav down and rebuilds it: identity on the left, clean tab states, subtitle with proper weight.

### Where

First story in v3 / EPIC-11 — no dependencies on other v3 US. Unblocks nothing directly but sets the visual baseline that all subsequent redesign stories (Setup, Deliverables, Board, Story Detail) will inherit for nav context. Pure frontend change to the shell component; no data layer touched.

## Plan

### Approach

- Unified shell in `MonitorHeader.tsx`: identity row, tab row with `border-b-2` active state, active-tab hint subtitle below tabs (`typeScale.bodySm`).
- `MonitorDashboard.tsx` wires `MonitorHeader` instead of separate top bar + tabs.
