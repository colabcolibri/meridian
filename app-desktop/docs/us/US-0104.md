# US-0104 — Extension onboarding and guide panels

**As** Process Manager using the Meridian VS Code extension,
**I want** clear, ordered instructions inside the IDE,
**so that** I know when to use extension commands versus chat slash workflows and do not confuse agents with workflows.

## Intent

### Acceptance

- [x] **How to Use** tab (`meridian.openHelp`) explains: setup steps, extension vs chat table, workflow → agent → skill diagram, reading order 1–4.
- [x] **Start Here** and **Usage Guide** editor tabs read `.agent/references/start-here.md` and `usage-guide.md` at runtime (same pattern as Agents Help).
- [x] **Commands sidebar** grouped: Guides (read first), Views, Governance, Kit setup.
- [x] **Command catalog** lists four guides with palette commands; kit group separated from guides.
- [x] **`usage-guide.md`** gains VS Code extension section (extension vs slash commands).
- [x] **`agents-help.md`** group count fix (six groups).
- [x] Extension **1.1.13** packaged: `meridian-vscode-1.1.13.vsix`; `README.md` and `CHANGELOG.md` updated.
- [x] Tests cover help HTML onboarding strings and `kitReferenceWebviewHtml`.

### Why

After v2.04, the extension exposed Board and project context but help was split: Command Help documented only Meridian:\* commands, while Start Here and Usage Guide existed in the kit without panels. Managers asked whether to call workflows or agents. This slice delivers the documented tríade (start-here → usage-guide → agents-help) plus a dedicated onboarding tab that states the rule: **you type workflows; agents follow**.
