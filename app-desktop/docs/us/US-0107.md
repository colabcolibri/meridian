# US-0107 — Migration script — import delivery artifacts from Markdown

**As** Process Manager,
**I want** a migration script that imports all existing epics, versions, sprints, and user stories from `.md` into SQLite,
**so that** Meridian v1 history is preserved when we cut over to the database-backed protocol.

## Intent

### Acceptance

- [x] `python3 .agent/scripts/migrate_md_to_sqlite.py <package-root>` reads `docs/epics/`, `docs/versions/`, `docs/sprints/`, `docs/us/`.
- [x] Reuses `validate_meridian.read_frontmatter()` and `meridian_section_contracts.extract_section_body()` for parsing — no third-party YAML dependency.
- [x] Prints summary table: entity type, files found, rows inserted, errors; exits 1 on any parse failure.
- [x] Dogfood counts: 14 epics (incl. EPIC-14), 15 versions (incl. v9), all sprints, 114 US (incl. US-0105–0114).
- [x] Upsert by primary key id — re-run updates existing rows without duplicates.
- [x] Preserves `status`, `ready`, `depends_on`, `moscow`, full Intent/Plan/Record/Boundaries sections.

### Why

The dogfood project has years of delivery history in Markdown. Losing a single US Record or acceptance checklist would break auditability. This script is the bridge from meridian-v1-old to Meridian 2.0 — it must be exhaustive and verifiable before any kit path stops writing `.md` files.

### Where

**v9-S2**, depends on **US-0106**. Blocks **US-0108** (decisions/board) and **US-0109** (validator on DB). Runs against `app-desktop/` during dogfood validation.

## Plan

### Approach

- Implement `migrate_md_to_sqlite.py` following `migrate_us_v2_structure.py` CLI pattern (`argparse`, `sys.path.insert` for `.agent/scripts` imports).
- Import order: versions → epics → sprints → user_stories → sprint_stories junction from sprint frontmatter `stories:` list, so FK constraints succeed on insert.
- Call `meridian_db.upsert_*()` helpers from US-0105 module; each upsert validates structure via `meridian_section_contracts` before commit (fail fast per file).
