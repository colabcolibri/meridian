# US-0084 — Deterministic open-folder reset and visible errors

**As** Process Manager,
**I want** every **Open folder** action to start from a clean slate and show a clear message when something fails,
**so that** I do not have to repeat the picker popup or guess whether the monitor is actually showing fresh data from disk.

## Intent

### Acceptance

- [ ] Clicking **Open folder** (welcome, header, top bar, guide callout) calls one shared `beginFolderOpen()` before the picker: bumps `restoreGenerationRef`, `userOpenGenerationRef`, and `openFolderGenerationRef`; clears `folderKey`, `folder`, and `docsRoot`; sets `status: opening` — same teardown as **Clear folder**, even when already open.
- [ ] Successful bind always assigns a new `folderKey` (`bindFolder` timestamp suffix); `ProjectDataContext` reloads from zero; Board/Deliverables/Setup show only data from the new bind — no stale cards, issues, badges, or open sheets from the previous key.
- [ ] **Zero silent failure:** no path sets `status: open` unless `bindFolder` succeeded in the current `openFolderGenerationRef`. On bind/validation failure after pick, `status` is `error` (or `permission_required` when awaiting grant), `folderKey` is `null`, and `error` is non-empty in welcome/header.
- [ ] Picker cancel (`AbortError`) restores the exact pre-open snapshot (status + binding) when a folder was open; otherwise `none` on welcome — never orphan `permission_required` without `handleRef` and grant CTA.
- [ ] Re-picking the same `docs/` path after editing files on disk updates the Board on the first successful open (new `folderKey` → full index reload) — no second **Open folder** required.
- [ ] `ProjectDataContext` background enrichment failure adds a visible `MonitorIssue` (error severity) instead of swallowing with `setBodyIssues([])` in an empty catch.
- [ ] Vitest unit tests cover the extracted state helpers / open generation guards (abort rollback, failure never → `open`, generation stale → no late bind).

### Why

Today `openFolder` only bumps generations and sets `opening` but leaves the previous `folderKey` until a new bind succeeds. On failure the catch block restores `status: "open"` when `folderKeyRef` was still set — the UI looks healthy while data may be stale or the pick never completed. Managers click **Open folder** again as a workaround. The fix is a explicit session state machine: reset → pick → bind or fail loudly; cancel rolls back; every async step checks generation before mutating React state.

### Where

**v2** / **EPIC-04**, after **US-0076** (index + `folderKey` reload). Depends on **US-0009** (picker + entry points). Unblocks dogfooding and **US-0051** / **US-0059** by making re-open reliable. Out of scope: Tauri restore (**US-0058**), file watcher without re-pick, multi-folder workspaces.

## Plan

### Approach

- Extract `folder-open-session.ts` with pure helpers: `createOpenSessionSnapshot(state)`, `resolveStatusAfterOpenFailure({ hadBoundFolder })` → always `error` when bind failed after reset (never `open`), and `shouldApplyAsyncResult(generation, currentGeneration)` — keeps `ProjectFolderContext` readable and testable without mounting React.
- Add `beginFolderOpen()` in `ProjectFolderContext.tsx`: save `priorOpenSessionRef` (status, folderKey, folder snapshot, handle ref) for abort rollback; increment all generation refs; call `clearBoundFolder()` and `setError(null)` before `pickMeridianFolder()` so `ProjectDataContext` clears data while `opening` (folderKey null).
- Refactor `openFolder` to: `beginFolderOpen()` → pick → permission branch → `finishOpenWithHandle` only if `openFolderGenerationRef` still matches; wrap `bindFolder` in generation check; on non-abort errors set `error` + `status: error` + clear binding — remove `folderKeyRef.current ? "open"` fallback in catch (lines 277–283 today).
- Refactor `clearFolder` to call `beginFolderOpen()` without picker (same generation semantics) then demo reload or `none` — one reset implementation for open vs clear.
- Align `grantReadPermission` with `openFolderGenerationRef` so late permission grants cannot bind after a newer open started.
- In `ProjectDataContext.tsx`, replace enrichment `.catch(() => setBodyIssues([]))` with a parse-scope error issue (`Story validation could not complete.`) so the issues banner always reflects failure.
- Add `project-folder-open.test.ts` (Vitest) for helpers + generation stale bind ignored; optional smoke test that documents the invariant list for manual QA.
