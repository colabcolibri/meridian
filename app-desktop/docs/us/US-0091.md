# US-0091 — Deliverables webview in VS Code extension editor tab

**As** Process Manager,
**I want** to browse product versions, sprints, and epics from Meridian docs inside the IDE,
**so that** I can see release structure and progress without opening the browser monitor.

## Intent

### Acceptance

- [x] **Meridian: Open Deliverables** command and Commands sidebar entry open an **editor tab** webview.
- [x] Data loaded from `docs/versions/`, `docs/sprints/`, `docs/epics/`, and US frontmatter in `docs/us/` for progress counts.
- [x] **Version filter** chips (multi-select; default latest) scope the list; empty selection shows a clear empty state.
- [x] **By version** layout: expandable version blocks with title/status, sprints for that version, epics with done/total story counts and progress bar.
- [x] Click version, sprint, or epic row opens the corresponding `.md` file in the editor (beside preview).
- [x] Refreshes when workspace `docs/` files change (same watcher as Board).
- [x] `pnpm compile` and `pnpm test` pass in `app-visual-studio/`.

### Why

v4 objective includes **Deliverables** alongside Board. US-0089 covers kanban only; managers still opened `docs/versions/` and `docs/epics/` by hand or switched to the browser app. This story adds the second primary read surface in the extension so day-to-day tracking stays in one installable product.

### Where

v4-S3 (replanned). Builds on US-0089 workspace detection and editor-tab pattern. Unblocks v4 go-live checklist item “Deliverables view” and doc sync in `05_architecture.md`. Sync/new-US commands remain deferred (v5).
