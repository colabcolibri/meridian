# US-0101 — Multi-product docs resolution (manifest A + discovery B)

**As** Process Manager,
**I want** several independent Meridian products in one repository each with its own `docs/` tree,
**so that** the IDE and agents target the correct product without hard-coded monorepo paths and without treating `docs-extra` as Meridian.

## Intent

### Acceptance

- [x] **Discovery B:** scan workspace for folders named exactly `docs` whose parent passes Meridian fingerprint (`00_scope.md` or `us/US-*.md` under that `docs/`).
- [x] **Manifest A:** optional `.meridian/projects.json` at kit root (`version`, `default`, `projects[]` with `id`, `name`, `docs` path, `exclude[]`) merges with discovery; manifest entries override names/ids; `exclude` removes paths from the picker.
- [x] **Active project:** setting `meridian.activeProject` + command **Meridian: Select Active Project**; status bar shows project name when N>1; board / deliverables / validate use active `docs/` and `packageRoot`.
- [x] **Kit docs:** `projects-manifest-template.md`, `usage-guide`, `start-here`, `init-project` skill, `status` workflow, `instruction-surfaces` — same A+B rules; only folder name `docs` counts.
- [x] **Tests:** `resolve-meridian-projects.test.ts` + updated workspace tests; `pnpm test` passes in `app-visual-studio/`.
- [x] **Validate:** `validate_meridian.py app-desktop` passes after architecture note update.

### Why

US-0042 resolved a single `docs/` with dogfood fallbacks (`docs`, `app-desktop/docs`). Real customer monorepos keep multiple products under `apps/*/docs`. Without a shared manifest and discovery contract, agents and the extension disagree on which tree is active. This story formalizes multi-product repos without reopening complete epics EPIC-05 or EPIC-12.

### Where

Release **v2.03** (`v2.03-S1`), **EPIC-13** (new capability). Depends on **US-0042** (extension workspace resolution) and **US-0100** (kit in external repos — manifest lives beside `.agent/`). Implementation was delivered before US authoring; this US retroactively documents and closes that delivery.

## Plan

### Approach

- **`resolve-meridian-projects.ts`** — pure discovery + manifest merge; `packageRoot` = parent of `docs/` path.
- **`meridian-workspace.ts`** — resolve active project from settings + default; no direct `vscode` import (picker split).
- **`meridian-workspace-picker.ts`** — Quick Pick UI + persist `meridian.activeProject`.
- **`meridian-context.ts`** — status bar label with project name; register `meridian.selectActiveProject`.
- **`validate-runner.ts`** — run Python validate on `packageRoot` not repo root when nested.
- **Kit** — template + guides; mirror via `sync_cursor_kit.sh` (manager runs after merge).
