# US-0092 — Board and Deliverables filter UX parity in extension

**As** Process Manager,
**I want** the same version filtering and working accordions in Deliverables as on the Board,
**so that** I do not relearn controls or fight broken UI when switching tabs.

## Intent

### Acceptance

- [x] **Board:** version and epic filters each have **All**, **None**, and multi-select chips (same behaviour as monitor `VersionFilterBar`).
- [x] **Board:** chip spacing (`gap` / margin) consistent on version and epic rows.
- [x] **Deliverables:** version toolbar matches Board (**All**, **None**, multi-select; **None** shows empty state, no auto-select-all).
- [x] **Deliverables:** version accordion **expand/collapse** works (chevron button only); version id opens file without breaking toggle.
- [x] **Deliverables:** sprint/epic rows use stable DOM (no broken `innerHTML` handlers).
- [x] `pnpm test` passes in `app-visual-studio/`.

### Why

US-0091 shipped Deliverables quickly; accordions did not open because the header click handler always bailed out, and version chips did not match the Board filter model the manager already learned. This story closes that gap before v4 go-live.

### Where

v4-S3 polish after US-0090/US-0091. Unblocks v4-S4 go-live smoke without UX regressions.

## Plan

### Approach

- Rewrite `deliverables-webview-html.ts` toolbar and accordion DOM (separate toggle vs open-link).
- Align `board-webview-html.ts` epic filter to `selectedEpics` Set like versions.
