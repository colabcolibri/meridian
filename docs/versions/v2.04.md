# v2.04 — Multi-product UI context

## Objective

US-0101 delivered resolver, manifest, and persistence hooks (`workspaceState`, `meridian.activeProject`), but the **visual surfaces** where managers work — Board, Versions, Sprints, Epics — still look like a single anonymous `docs/`. Reopening a tab does not explain which product is loaded; the only hint is the status bar when N>1.

This release adds a **project context strip** in every Meridian webview and tab titles that name the active product and `docs/` path. The active project remains **saved** between sessions and panel reopens; switching updates persistence and refreshes open Meridian tabs without asking again on every Board open.

## Done criteria

With two Meridian `docs/` trees, the manager selects **App OSC** once, closes and reopens Board — still **App OSC**, path visible in the toolbar, no forced picker. They switch to **Sistema** from the Board header (or status bar / command); all open Meridian panels refresh to the new `docs/`. Single-project repos still show the relative `docs/` path for clarity.
