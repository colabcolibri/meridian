# v2.02 — Kit distribution

## Objective

Since v0, the Meridian kit (`.agent/`) lived inside the monorepo and US-0006/US-0007 explicitly deferred a **CLI installer** for external projects. Managers who want only the protocol — agents, skills, workflows, validator — still copy folders by hand or rely on git clone of the full repo. v2.02 delivers a **standalone meridian-kit package**: tarball without `app-desktop/`, an install script that replaces `.agent/` on upgrade, and **surgical** sync of `.cursor/` and `.claude/` adapters so user-owned content in those folders is never deleted.

## Done criteria

A manager can download or build `meridian-kit-VERSION.tar.gz`, run `install.sh` (or `install-meridian-kit.sh`) in an external project, run `/init-meridian` if needed, and open the project in Cursor or Claude Code with working slash commands and skills. Re-running install with `--force` upgrades `.agent/` and refreshes Meridian symlinks only — orphan kit symlinks are removed, real files and non-Meridian symlinks stay untouched. Dogfood install is documented in `.agent/KIT_README.md` and `IDE_ADAPTERS.md`; `validate_meridian.py` passes on a fresh external tree.

## Explicitly out

- `npx` or npm-published CLI (remains optional future; bash scripts are the v2.02 deliverable).
- VS Code extension distribution (v4 `.vsix` is separate).
- Automatic `docs/` bootstrap beyond pointing to `/init-meridian`.
- Windows native installer (bash + documented manual steps only).
