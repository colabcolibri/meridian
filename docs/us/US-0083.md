# US-0083 — Open user story sheet from sprint deliverable

**As** Process Manager,
**I want** to open a user story detail sheet from the sprint deliverable panel while keeping the sprint sheet open,
**so that** I can read sprint context and drill into individual stories without losing my place in the release plan.

## Intent

### Acceptance

- [x] Sprint deliverable sheet lists each `storyIds` entry as a clickable row (id + title when loaded), not plain comma-separated text.
- [x] Clicking a loaded US opens `StoryDetailSheet` on top of the sprint sheet (same content as Board card click: summary, done_when, epic, alerts, markdown body).
- [x] Closing the story sheet (X or overlay) leaves the sprint sheet open; closing the sprint sheet closes both.
- [x] Nested sheet uses a higher stack layer so focus and overlay behave correctly with two sheets open (sprint base, story nested).

### Why

Today the sprint side panel shows linked US as a single line (`US: US-0081, US-0082`). The manager must close the sprint, find the story on the Board or in files, and reopen detail — which breaks the planning flow when reviewing what a sprint commits to deliver. After this slice, sprint review stays in Deliverables: open sprint, tap a story, read full US, close story, continue reading the sprint markdown.

### Where

Follow-up in v3 / EPIC-11 after US-0081 (Story Detail redesign) and US-0079 (Deliverables redesign). Reuses `StoryDetailSheet` and on-demand markdown load from US-0076; no new parser fields or disk writes. Does not add the same drill-down to version or epic sheets in this story.

## Plan

### Approach

- Replace the sprint summary line in `deliverable-doc-sheet.tsx` with `SprintStoriesSummary`: one button per `sprint.storyIds`, resolving title from the in-memory `stories` index; disabled state when an id is missing from the loaded project.
- Keep sprint `MarkdownDocSheet` open and render a second `StoryDetailSheet` with `stackLayer="nested"` and local `nestedStory` state; clear nested selection when the sprint sheet closes or the deliverable target is no longer a sprint.
- Extend `sheet.tsx` / `MarkdownDocSheet` with `stackLayer` (`base` | `nested`) so overlay z-index and `modal={false}` on the nested sheet avoid trapping focus on the parent sprint panel.
- Thread `epics` and `issues` into `DeliverableDocSheet` from `DeliverablesView` / `EpicDeliverablesPanel` so nested `StoryDetailSheet` shows epic title and protocol alerts via `issuesForTarget`, matching Board behavior.
