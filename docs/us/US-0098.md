# US-0098 — Board kanban per-column pagination and All default filters

**As** Process Manager,
**I want** the Board to open with all versions and epics visible and paginate cards independently in each column,
**so that** I see the full project kanban without re-selecting filters and can browse large Done/Todo columns without lag.

## Intent

### Acceptance

- [x] Board opens with **All versions** and **All epics** selected (same default as Sprints/Epics list views).
- [x] Toolbar **Show** selector sets cards per column (25 / 50 / 100; default 50).
- [x] Each column (Todo, Partial, Tests, Done, Frozen) has its own **◀ / ▶** pager and range (`1–50 / 87`); changing one column does not change others.
- [x] Filter or page-size changes reset column pages; column page state persists in webview session.
- [x] `pnpm test` includes `board-payload.test.ts` (all versions default).

### Why

US-0090 defaulted to the latest version only — managers reviewing cross-release work had to click All every session. Large Done columns with every version selected need the same bounded-list pattern as US-0097, but **per column** because kanban columns have different card counts.

### Where

v4-S7 after US-0097 list pagination. Completes EPIC-05 read-surface polish before v5 authoring wizards.

## Plan

### Approach

- `buildBoardPayload` uses `allSelectedVersionIds`; `BOARD_STATE_VERSION` resets stale filter state.
- `board-webview-html.ts`: `columnPages` keyed by stable ids (`todo`, `done`, …); `refreshColumn` updates one column only on pager click.
- Reuse `PAGINATION_SCRIPT` from `webview-common.ts`.
