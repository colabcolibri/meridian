# US-0081 — Story Detail redesign

**As** Process Manager,
**I want** the Story Detail panel to present user story content in a structured, readable layout,
**so that** I can review a story's intent, acceptance criteria, and status without wading through raw file data.

## Intent

### Acceptance

- [x] The Story Detail panel does not display raw YAML frontmatter at the top — metadata fields (version, status, epic, moscow, depends_on) are rendered as structured UI elements (badges, labels, or a metadata row).
- [x] The panel has a clear two-zone layout: a metadata header (id, title, status, epic, version, moscow) and a content body (the rendered Markdown sections).
- [x] Acceptance criteria checkboxes in the Intent section are rendered as visual checklist items, not raw Markdown `- [ ]` text.
- [x] The panel header includes a close button and the US file path as a secondary label for traceability.

### Why

Today the Story Detail opens with a block of raw YAML — `version: v1`, `status: ✅`, `moscow: Must`, `depends_on:` — displayed verbatim at the top, as if the file was opened in a text editor. This is the first thing a user sees when clicking a board card, and it immediately signals "this is a developer tool, not a product." Below the YAML, the Markdown content renders reasonably, but the frontmatter exposure undermines the whole panel. This story removes the raw YAML and replaces it with a designed metadata header, then ensures acceptance criteria render as interactive (or visual) checklists.

### Where

Fifth story in v3 / EPIC-11 — depends on US-0080 (Board redesign, since the panel is triggered from a card click). Touches the story detail panel/modal component and its Markdown renderer. No changes to how US files are parsed or loaded. Completing this story closes EPIC-11 core deliverables.

## Plan

### Approach

- `hideFrontmatter` prop on `MarkdownDocSheet` / `StoryDetailSheet`.
- Structured `summary` panel before markdown body; badges in sheet header.
- `MarkdownContent` uses `remark-gfm` for task-list checkboxes.
