# US-0090 — Board filter toolbar in VS Code extension editor tab

**As** Process Manager,
**I want** to filter the kanban board by version, epic, and frozen stories in the IDE,
**so that** planning sessions focus on the release and capability I am reviewing without noise from other versions.

## Intent

### Acceptance

- [x] Board opens in an **editor tab** (not sidebar) via **Meridian: Open Board** or Commands tree.
- [x] Toolbar above columns: **version** chips (multi-select; default latest version), **epic** chips (scoped to selected versions; **All** resets epic), **Show frozen** toggle hiding/showing column 🧊.
- [x] Summary shows count of stories matching the active filter.
- [x] Filter choices persist in the webview session (`vscode.setState`) until the tab is disposed.
- [x] Column rules unchanged from US-0089 (❌ 🔶 🧪 ✅ 🧊); card click still opens `docs/us/US-XXXX.md`.
- [x] `pnpm compile` and `pnpm test` pass in `app-visual-studio/`.

### Why

US-0089 delivered a full kanban but every US in `docs/us/` appeared at once — the same pain the browser monitor solved with version and epic filters. This story adds **read-only filtering** only: no new data sources, no writes. After it ships, the manager opens Board in the IDE and narrows to e.g. v4 + EPIC-05 before a sprint review.

### Where

v4-S2 follow-up (board polish). Depends on US-0089 (parser, editor tab, column logic). Unblocks US-0091 (Deliverables can reuse version chip UX). Out of scope: MoSCoW filter, drag-and-drop, layout “by epic” columns.

## Plan

### Approach

- Extend `board-webview-html.ts` with a toolbar and client-side filter over the stories JSON payload.
- Add `domain/version-filter.ts` and `load-epics.ts` for version ordering and epic labels.
- Pass full `stories` + epic summaries from `board-editor-panel.ts` instead of pre-grouped columns server-side.
