# US-0105 — SQLite schema for delivery artifacts

**As** Process Manager,
**I want** a versioned SQLite schema that models epics, versions, sprints, user stories, and decisions,
**so that** delivery data has one structured source of truth instead of hundreds of Markdown files.

## Intent

### Acceptance

- [x] SQL migration file `.agent/migrations/YYYYMMDDHHMMSS_initial_delivery_schema.sql` creates tables: `schema_migrations`, `epics`, `versions`, `sprints`, `sprint_stories`, `user_stories`, `decisions`, `board_snapshots`.
- [x] Frontmatter fields are typed columns (`id`, `title`, `status`, `moscow`, `ready`, `tests`, `tests_status`, `depends_on` as JSON text); body sections (`intent_acceptance`, `intent_why`, `intent_where`, `plan_approach`, `plan_architecture_refs`, `record_*`, `boundaries_*`) stored as TEXT.
- [x] Foreign keys: `user_stories.epic_id` → `epics.id`, `user_stories.version_id` → `versions.id`, `sprints.version_id` → `versions.id`, `sprint_stories` junction with `(sprint_id, story_id)`.
- [x] `schema_migrations` table tracks applied migration filenames.
- [x] `06_database.md` draft updated with ER summary and table list referencing the migration file.

### Why

Meridian v1 stores every artifact as a separate `.md` file with YAML frontmatter. Parsing is fragile, queries are slow, and the monitor must glob entire trees. Before any migration or kit rewrite, we need a stable relational model that captures every field the validator and `section-contracts.md` require — without losing section structure.

### Where

First slice of **v9 / EPIC-14** (`v9-S1`). Blocks **US-0106** (bootstrap) and **US-0113** (documentation). Unblocks all migration and kit stories in v9-S2 and v9-S3.

## Plan

### Approach

- Add `.agent/migrations/20260718100000_initial_delivery_schema.sql` with `CREATE TABLE IF NOT EXISTS` for all delivery entities; enable `PRAGMA foreign_keys = ON` in the migration runner, not in the SQL file alone.
- Create `.agent/scripts/meridian_db.py` with `resolve_db_path(package_root)`, `connect()`, `apply_migrations()`, and `list_tables()` — shared module imported by bootstrap, migrate, and validate scripts (DRY; mirrors `meridian_section_contracts.py` pattern).
- Map `depends_on` and `sprint.stories` as JSON arrays in TEXT columns validated at insert time by reusing `meridian_section_contracts.validate_*_structure()` on reconstructed markdown stubs before write (validation logic stays in existing module).
