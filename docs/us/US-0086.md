# US-0086 — By-epic board spacing and status summary on epic rows

**As** Process Manager,
**I want** the By epic board list to breathe at the top and each epic row to show how many stories sit in each status column,
**so that** I can scan epic health without expanding every accordion.

## Intent

### Acceptance

- [x] In "By epic" layout, the vertical list of epic accordion rows has visible top spacing (padding or margin) so the first row is not flush against the filter bar / board chrome — consistent with the column layout inset (`p-3` on the board body, not `pt-0` on the epic list alone).
- [x] Each epic row header (collapsed or expanded) shows a compact status summary: counts for Pending (❌), In progress (🔶), Awaiting tests (🧪), and Complete (✅), using the same `resolveKanbanColumn` / `groupStoriesForKanban` rules as the inner column grid for that epic's filtered stories.
- [x] Frozen (🧊) appears in the summary only when that epic has at least one frozen story in the current filter; when the board's "Show frozen" control is off, frozen counts are omitted from the summary even if frozen stories exist (same visibility rule as the inner columns).
- [x] Summary segments with count `0` are hidden so the header stays scannable; the existing `done/total` fraction stays at the end of the row (unchanged semantics from `countStoryProgress`), with column counts shown before it on viewports `sm+` (wraps on narrow screens without horizontal overflow).
- [x] Version and epic filters still apply; changing filters updates both inner grids and header summaries without resetting layout toggle or accordion open state beyond existing US-0082 behavior.

### Why

US-0082 added the By epic accordion with `done/total` only. In practice the first epic toggle sits too close to the controls above (`pt-0` on the list wrapper), and a single fraction does not say whether work is blocked in Pending, stuck in Awaiting tests, or already Complete. The manager still expands every epic to read the inner columns. This slice fixes spacing and surfaces the same column counts on the row header, reusing existing kanban grouping — no new data or persistence.

### Where

Follow-up in v3 / EPIC-11 after US-0082 (grouped-by-epic layout). Touches `KanbanView` / `EpicKanbanGroup` only; column view unchanged. Does not change card design, Story Detail, or board.json generation.

## Plan

### Approach

- Change the By epic list wrapper in `KanbanView.tsx` from `p-3 pt-0` to `p-3` (same inset as the column grid body) so the first `EpicKanbanGroup` is not flush against the filter bar; do not add extra margin only on the first child — one consistent padding on the scroll container.
- Add `countKanbanColumns(stories, options: { showFrozen })` in `src/domain/meridian/kanban-columns.ts` that maps `groupStoriesForKanban` + `visibleKanbanColumns` into ordered pairs so header summaries and the inner grid cannot drift; cover 🧪 derivation and frozen visibility in `kanban-columns.test.ts`.
- `EpicKanbanStatusSummary` co-located in `KanbanView.tsx`, reuses `columnMeta`, renders only segments with `count > 0`, omits 🧊 when `showFrozen` is false.
- `useMemo` for `countKanbanColumns(epicStories, { showFrozen })` beside `countStoryProgress` in `EpicKanbanGroup`.
- Collapsible open/close behavior from US-0082 unchanged.
