# US-0076 — Lightweight project index on folder open

**As** Process Manager,
**I want** the monitor to open my docs folder quickly without loading every markdown file into memory,
**so that** I can review Setup, Deliverables, and Board without infinite loading or waiting for a full snapshot.

## Intent

### Acceptance

- [x] Opening `app-desktop/docs/` finishes index build in under 3 seconds on a typical dev machine (no full-body read of all `us/*.md` at open).
- [x] Kanban, Deliverables, and Setup tabs show the same frontmatter-driven data as today (status, epic, version, phase doc states, epic/version lists).
- [x] `StoryDetailSheet`, `PhaseDocReader`, and `MarkdownDocSheet` read the full file from the folder handle when opened — not from a global `storyBodies` / `epicBodies` map populated at load time.
- [x] `MonitorIssuesBanner` still lists protocol issues equivalent to today (index-level checks at open; body-dependent rules may run lazily or on sheet open if documented in Approach).
- [x] `pnpm test` and `pnpm build` pass; dogfooding with 75+ US does not show indefinite “Loading project…”.

### Why

Today `loadMeridianProject()` reads and parses every phase doc, user story, epic, version, sprint, and decision file into a single `MeridianProjectData` object in React state. That snapshot model is slow, fragile (race conditions leave loading stuck), and duplicates what already lives on disk. This story replaces the monolithic load with a **light index**: list files, parse frontmatter (and minimal phase metadata), derive the board from US frontmatter, and keep the `FileSystemDirectoryHandle` as the live mirror. Full bodies load only when the manager opens a reader — matching how the protocol treats `docs/` as source of truth.

### Where

Part of **v2** / **EPIC-04**, sprint **v2-S6**. Depends on US-0009 (folder handle), US-0016 (no mock — folder is sole source), and US-0014 (protocol alerts must remain visible). Unblocks reliable dogfooding while v2 extension work continues and de-risks **US-0059** (file watcher) by shrinking what must refresh on change. Does not deliver Tauri, OS-level watch, or write path.

## Plan

### Approach

- `readTextFileForFrontmatter` reads up to 8KB per US file for YAML-only index; full file only when frontmatter does not fit in prefix.
- `loadMeridianProject` returns `MeridianProjectData` without body maps; epic/version structure validation runs at parse time without storing bodies.
- `collectIndexProtocolIssues` runs at index open; `enrichUserStoryValidation` loads US bodies in background after `loading` is false and merges issues + doc badges.
- `ProjectDataContext` two-phase load fixes `opening` status leaving spinner stuck; sheets already used `readMarkdownDocFromFolder` on demand.
