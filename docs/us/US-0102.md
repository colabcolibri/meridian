# US-0102 — Project context strip in Board and Deliverables

**As** Process Manager,
**I want** to see which Meridian product and `docs/` folder Board and Deliverables are using — and have that choice remembered when I close and reopen tabs,
**so that** I never confuse two products in a monorepo and can switch projects easily only when I need to.

## Intent

### Acceptance

- [x] **Context strip:** first toolbar row in Board, Versions, Sprints, and Epics shows **Project** label, active **name**, relative **`docs/` path** (monospace), and **US count** for that tree.
- [x] **Persisted active project:** reopening any Meridian editor tab loads data from the **same** active project saved in `workspaceState` (per kit root) or `meridian.activeProject` — **no** repeat Quick Pick on every Board open when a choice already exists.
- [x] **First visit only:** Quick Pick appears only when N>1 projects and **no** stored id and **no** setting — same rule as US-0101; after first choice, subsequent opens are silent.
- [x] **Switch in UI:** when N>1, a **dropdown** in the context strip lists projects; changing selection persists id, refreshes **all open** Meridian webview panels, and shows a short confirmation (toast).
- [x] **Tab titles:** VS Code panel title includes project name when N>1 (e.g. `Board — App OSC (42)`); when N=1, title includes relative `docs/` path (e.g. `Board — app-desktop/docs (42)`).
- [x] **Parity:** status bar and **Meridian: Select Active Project** use the same `switchActiveMeridianProjectById` persistence; context strip updates on refresh.
- [x] **Tests:** `webview-project-context.test.ts`; `pnpm test` — 41 passed.

### Why

US-0101 wired resolver and persistence under the hood, but the kanban and deliverables screens still look like one product. A manager opening **Board** after working on **Sistema** cannot tell which `docs/` is on screen without hunting the status bar. Worse, without explicit acceptance on **reopen behaviour**, it is unclear whether each open should re-ask — the expected behaviour is **remember until I change it**. This slice makes the active `docs/` **visible and stable** in the places where US and versions are read.

### Where

Release **v2.04** (`v2.04-S1`), continuation of **EPIC-13**. Depends on **US-0101** (`workspaceState`, manifest, resolver). Extension release **1.1.10** ships with this US.

## Plan

### Approach

- Add **`webview-project-context.ts`** with `buildWebviewProjectContext`, `formatMeridianPanelTitle`, shared toolbar HTML/CSS/JS so Board and Deliverables stay consistent without duplicating four webviews.
- Prepend **project context row** to existing `.toolbar` in `board-webview-html.ts`, `versions-webview-html.ts`, `sprints-webview-html.ts`, `epics-webview-html.ts`; payload carries `context` built from `MeridianWorkspaceInfo` at refresh time.
- Wire **`postMessage` `{ type: "selectProject", id }`** from webview dropdown through `BoardEditorPanel` and `DocsOpenPanel` to **`MeridianContext.selectActiveProjectById`**, which calls **`switchActiveMeridianProjectById`** in `meridian-workspace-picker.ts` (same persistence as Quick Pick — no fork).
- **`refreshAllPanels`** on project change reloads open tabs with new `docsRoot`; reopening a closed tab reads stored id via existing `pickMeridianWorkspace` — no repeat picker.
