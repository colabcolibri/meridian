# US-0082 — Board grouped-by-epic accordion layout

**As** Process Manager,
**I want** to switch the Board to a grouped-by-epic view where each epic is an accordion row containing its stories by status,
**so that** I can review progress per epic at a glance without stories from different epics mixing in the same column.

## Intent

### Acceptance

- [x] A layout toggle (e.g. "Columns / By epic") appears above the kanban board, consistent with the existing filter bar.
- [x] In "By epic" mode, each epic with visible stories renders as a collapsible accordion row showing the epic ID, title, and a compact progress indicator (done/total).
- [x] Inside each expanded epic row, stories are grouped into the same status columns (Pending, In progress, Awaiting tests, Complete, Frozen) — same column structure as the default view, scoped to that epic.
- [x] Version and epic filters apply to both layout modes — switching layout does not reset filter state.

### Why

Today the Board mixes all epics in the same columns — when a version has 4–5 active epics, the Complete column fills with stories from different epics and it becomes hard to assess which epic is actually done versus which has stragglers. The epic filter helps but requires switching back and forth. A grouped view lets the manager see all epics at once, each with its own status breakdown, without losing the column mental model. This story adds that as a toggleable layout — the current column view remains the default.

### Where

Sixth story in v3 / EPIC-11 — depends on US-0080 (Board redesign, which established the unified filter bar and column structure). The epic grouping uses data already loaded (`epics`, `stories` with `epic` field). No new data fetching or backend change. The layout toggle state can be local to `KanbanView` — no persistence needed unless a future story adds it.
